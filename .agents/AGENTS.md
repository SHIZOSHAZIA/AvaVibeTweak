# Правила разработки проекта AvaVibeTweak

## Важное правило по перехвату событий (Hit-Testing & Pointer Interception)
**ОБЯЗАТЕЛЬНО К ИСПОЛНЕНИЮ АВТОМАТИЧЕСКИ:**
Поскольку AvaVibeTweak работает как оверлей и перехватывает клики мыши на чужом интерфейсе (через глобальный `OnPointerMoved` и `OnPointerPressed`), необходимо **категорически избегать** перехвата кликов на **собственных окнах и попапах** самой утилиты.

- **Суть проблемы**: Уже несколько раз происходила ситуация, когда утилита пыталась "редактировать саму себя", например, вешала розовую рамку выделения на `ColorPicker` или окно `SettingsView`.
- **Решение**: Любое новое окно, всплывающее меню (Popup), или диалог, создаваемые внутри `AvaVibeTweak.UI.Views`, **ОБЯЗАНЫ** быть добавлены в исключения в методе `IsPanelOrPopupElement` внутри `VibeOverlayManager.cs`. 
- **Реализация**: Используйте проверку по типу (например, `if (current is AvaVibeTweak.UI.Views.МоеНовоеОкно) return true;`), а также поднимайтесь по логическому дереву (`LogicalParent`), чтобы корректно отлавливать элементы внутри Popups. Никогда не забывайте про это при создании новых элементов UI для утилиты!
