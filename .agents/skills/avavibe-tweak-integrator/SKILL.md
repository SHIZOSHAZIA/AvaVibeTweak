# AvaVibeTweak Integrator Skill

Этот навык определяет жесткие правила для агента при переносе визуальных изменений из файла `vibe_patch.json` (сгенерированного библиотекой AvaVibeTweak) в исходный код Avalonia UI (`.axaml`).

## Твоя роль
Ты выступаешь в роли моста между визуальным редактором AvaVibeTweak и исходным кодом. Разработчик использует AvaVibeTweak для визуальной настройки UI и сохраняет "черновик" в `vibe_patch.json`. Твоя задача — безопасно, умно и с учетом всех нюансов Avalonia перенести эти настройки в `*.axaml` файлы и удалить черновик.

## Алгоритм работы (Строго следовать!)

### 1. Парсинг Visual Tree Path
- Внимательно прочитай пути в `vibe_patch.json` (например: `MainWindow > Grid[0] > Button#BtnOverview > PART_ContentPresenter`).
- Найди соответствующий `.axaml` файл.
- **Внимание (UserControls):** Если путь указывает на элемент, который находится внутри `UserControl` (например, `MainWindow > MyCustomCard > TextBlock`), открой файл `MyCustomCard.axaml` и ищи элемент там.

### 2. Защита шаблонов и списков (КРИТИЧНО)
Если путь заканчивается на элемент с индексом (например, `ContentPresenter[3]`) внутри `ItemsControl` или `ListBox`:
- Это значит, что разработчик редактировал один из сгенерированных элементов списка.
- **ЗАПРЕЩЕНО** изменять исходный `DataTemplate` без спроса.
- **Обязательное действие:** Спроси пользователя: *"Вы редактировали элемент списка с индексом [N]. Хотите ли вы применить этот дизайн ко ВСЕМ элементам списка (изменив DataTemplate) или ТОЛЬКО к элементу с этим индексом (я сгенерирую Avalonia `<Style Selector="...:nth-child(N)">`)?"*

### 3. Защита привязок (Bindings) и Ресурсов (Resources)
Если ты собираешься перезаписать свойство (например, `Text: "$45"` или `Background: "Red"`):
- Проверь, как это свойство задано в AXAML сейчас.
- Если там стоит привязка `{Binding ...}`, `TemplateBinding` или `{DynamicResource ...}` — **ЗАПРЕЩЕНО** заменять её на жесткое значение из патча. 
- **Обязательное действие:** Сохрани оригинальный Binding/Resource, примени только безопасные визуальные свойства (Padding, Margin и т.д.) и уведоми пользователя: *"Я проигнорировал свойство [ИмяСвойства], чтобы не сломать вашу привязку данных/ресурсов"*.

### 4. Защита внутренних шаблонов Avalonia (ControlTheme)
Если путь ведет глубоко во внутренности стандартного контрола Avalonia (например, `ScrollViewer` внутри `ListBox` или `PART_Track` внутри `Slider`):
- **Обязательное действие:** Предупреди пользователя: *"Вы пытаетесь изменить базовый шаблон Avalonia. Для этого мне нужно сгенерировать кастомный `ControlTheme` в ваших ресурсах. Сделать это?"*

### 5. Динамические элементы (Code-Behind)
Если элемента нет в AXAML, но он есть в пути:
- Вероятно, он создан через C# `new TextBlock()`.
- Найди его создание в code-behind (например, `MainWindow.axaml.cs`) и примени стили там.

### 6. Завершение работы
После того как все безопасные свойства успешно перенесены в `.axaml`:
- Выполни сборку `dotnet build`, чтобы убедиться, что XAML валиден.
- Предложи разработчику **удалить** отработанный файл `vibe_patch.json`.
