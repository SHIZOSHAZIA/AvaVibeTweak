# Архитектурная спецификация: AvaVibeTweak

## 1. Проблематика (The Problem)
В процессе работы с ИИ-ассистентами (Vibe Coding) создание базовой структуры UI проходит отлично, но тонкая визуальная настройка ("pixel-hunting") через текстовые запросы крайне неэффективна. Объяснение ИИ, что нужно сдвинуть кнопку на 5 пикселей левее или сделать цвет чуть темнее, тратит много времени, токенов и контекста.

## 2. Концепция (The Solution)
**AvaVibeTweak** — это универсальная, подключаемая библиотека (In-App Overlay) для Avalonia UI. Она позволяет разработчику запускать свое приложение, нажимать горячую клавишу и визуально "дотягивать" интерфейс мышкой прямо в работающей программе. После настройки генерируется патч-файл (`vibe_patch.json`), который ИИ-ассистент считывает и вносит точные изменения в исходный код `.axaml`.

## 3. Требования к универсальности
Библиотека должна быть абсолютно универсальной:
- Она должна работать в **любом** проекте на Avalonia UI 11+ (.NET 8/9).
- Она **не должна зависеть** от того, какой паттерн (MVVM, MVC) или фреймворк (ReactiveUI, CommunityToolkit) использует пользователь.
- Она **не должна изменять** визуальное дерево приложения (чтобы не сломать чужие Grid и StackPanel) в процессе своей отрисовки.

## 4. Техническая архитектура

### 4.1. Формат и Интеграция
- **Формат**: Обособленная C# Class Library.
- **Подключение (Zero-Config)**: Интеграция должна занимать ровно одну строку. Будет создан `AppBuilderExtension` с методом `UseAvaVibeTweak()`. 
```csharp
// Пример интеграции в чужом Program.cs
AppBuilder.Configure<App>()
    .UsePlatformDetect()
    .UseAvaVibeTweak() // Инъекция
    .LogToTrace();
```

### 4.2. Механизм перехвата интерфейса (Global Hooks)
Библиотека не должна требовать добавления контролов в `MainWindow.axaml`. 
- Перехват интерфейса происходит на этапе инициализации приложения.
- Используется глобальный доступ через `TopLevel.GetTopLevel(...)` для навешивания глобальных обработчиков событий мыши (`PointerMoved`, `PointerPressed`), чтобы перехватывать клики до того, как они уйдут в бизнес-логику приложения.

### 4.3. Отрисовка рамок и оверлея
- Для подсветки элементов при наведении и отрисовки рамок выделения **обязательно использование `Avalonia.Controls.Primitives.AdornerLayer`**. Это специальный слой рендеринга поверх всего окна, который гарантирует, что наша подсветка не сдвинет ни один пиксель пользовательской верстки.

### 4.4. Управление и Панель свойств
- **Активация**: Переход в режим "Дизайна" и обратно осуществляется строго по нажатию клавиши `F11`.
- **UI Редактора**: При клике на элемент в режиме дизайна должна появляться компактная плавающая панель (сделанная тоже через AdornerLayer или Popup) с настройками.
- **Поддерживаемые свойства (на старте)**:
  - `Margin`
  - `Padding`
  - `Width` / `Height`
  - `Background` / `Foreground`
  - `FontSize`

### 4.5. Генерация патча (Export)
Внесенные изменения аккумулируются во внутреннем словаре. При сохранении генерируется файл:
- **Название**: `vibe_patch.json`
- **Место сохранения**: Строго в корневую директорию проекта (там же, где лежит `.sln` или главный `.csproj`).
- **Формат**: Имя элемента (x:Name или уникальный путь) -> список измененных свойств и их новые значения.

## 5. Роль ИИ и Open Source
Проект планируется как Open Source решение (GitHub / NuGet). 
В экосистеме IDE Antigravity будет создан специальный Скил, который:
1. Автоматически скачивает `AvaVibeTweak` для новых проектов пользователя.
2. Прописывает его интеграцию.
3. Парсит `vibe_patch.json` и делает точечные `replace_file_content` в файлах `*.axaml`, завершая цикл визуального редактирования.
